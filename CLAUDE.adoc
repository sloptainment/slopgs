== What slopgs is

A clean-room re-implementation of `swmidi.sys` (MSGS) as shipped with Windows
XP SP3. The aim is a clone that *sounds identical*, quirks included.

== Workflow

When a *behavioral finding changes* (something the driver does is newly
known, or an assertion is now known to be wrong) work in **exactly this
order**, finishing each step before the next:

. `src/unit.c`: add or replace the assertion, with its evidence in the
  description, and confirm `make unit` fails. *Red.*
. The engine under `src/`: implement until the assertion passes and the
  corpus gate holds: targeted item improves, mean does not regress. *Green.*
. Optimize what you just added while both stay green. *Refactor.*
. `INVESTIGATE.adoc`: delete what this closed; add what it opened.
. `impl-chart/CHART.adoc`: if a musician would notice, suggest changes to
  the user, who edits it.

**Whenever a `unit.c` assertion and `src/` disagree, the assertion wins**: the
fix is the engine. Only new evidence from the binary or a measurement may
change what it asserts.

The one exception: if matching the driver regresses the corpus mean, ship
the fit instead, mark the assertion `todo_ok` with an `INVESTIGATE.adoc` id,
and record both A/B numbers in that entry.

== Where to go

=== `artifacts/`

Your primary experimental workspace.

`swmidi.sys`:: The driver binary: the evidence for driver questions.

`INVESTIGATE.adoc`:: Everything unresolved: driver behavior not yet
recovered, engine behavior that knowingly differs from the driver, and the
justification of every fitted (`[F]`) value: the value, what it was fit
against, the metric, and where a future pass should look to retire it.
+
Navigate it by grep: `grep -n '^== ' artifacts/INVESTIGATE.adoc` lists every
entry by id; jump with `grep -n '\[#i-release-floor\]'` and read ~40 lines.
Source comments and `todo_ok` reasons cite entries as
`INVESTIGATE.adoc#i-…`. Each entry is *Known* / *Open* / *Settle by* /
*Where*. Delete an entry once it is closed; the assertion is the record.

`impl-chart/CHART.adoc`:: The user-facing *MIDI Implementation Chart*: what a
musician should expect, matching `unit.c` and the engine, free of internal
code details.

`make_probes.py`:: Generates deterministic MIDIs into `probes/`, each
testing one behavior; references go in `probe-results/`. The GS Sine Wave
patch (`008:080`) makes clean probes.

`score.py`:: The corpus gate: scores every MIDI that has a reference FLAC
under `field/`, `tests/` and `probes/`. Ask the user to record any missing
reference. Needs the venv
(`python3 -m venv .venv && .venv/bin/pip install -r requirements.txt`) and
`ffmpeg`; ~25s for the full corpus.
+
[source,console]
----
$ .venv/bin/python artifacts/score.py                 # everything
$ .venv/bin/python artifacts/score.py 20 HueArme-Weekend   # named items
$ MSGS_RENDER=/path/to/other-build .venv/bin/python artifacts/score.py   # A/B a build
----
+
The `dead` column reports milliseconds of digital silence in the render that
the reference does not have. Read it on `field/` items only: a sparse probe's
reference never drops below the threshold (dither), so its genuine
inter-case gaps all count.

=== `src/engine/`

Freestanding C: no libc, libm, malloc or stdio. `rt.c` supplies
`memcpy`/`memset`/`pow`/`log10`/`sqrt`/`sin` and a bump allocator; plain
IEEE-754 `double` is all the arithmetic needs. `gm.dls` is parsed in place
and sample data is referenced, never copied. The ABI in `msgs.h` is fixed.
`smf.c` has no counterpart in the driver. Target-specific code (`wasm.c`,
`cli.c`) lives in `src/`.

=== `tests/`, `field/`

`tests/`: MIDIs for behavior a generated probe can't pin down, one reference
FLAC each. `field/` (optional): real-world MIDIs with reference FLACs.

=== `dist/`

`gm.dls` is user-supplied. `compare.js` holds the spectrogram code for the
`compare-*.html` pages. The user serves the repo root over HTTP.

== What "identical" means

Indistinguishable at a casual listen, and measurably near-identical,
especially on specific synth behavior.

=== Measuring

References are captured on an emulated XP guest through host loopback, not
from the driver's buffer: ±1 LSB dither per channel, so bit-exactness cannot
be shown. Repeat captures agree to ~1% on percussive attacks and ~0.02% on
sustained tones; pick the tolerance by signal type.

. Resample the reference to 22050 Hz, the driver's only rate.
. Normalize for dither.
. Align the two (start delays differ), e.g. by RMS-envelope or FFT
  cross-correlation.
. Compare analytically and visually; when one is inconclusive, use the
  other.

Analytical:: Peak/RMS/spectral dB residual per probe (nearer 0 dB is worse),
and envelope correlation `r` against the reference track.
Visual:: Large spectrograms of both, labelled `slopgs` and `reference`.

=== Confirming

Ask the listener to audition the probes and, for any deviation, report the
time, the measure (infer it from the timestamp if they can't), and the
instrument. A passage they isolate becomes a `tests/` item; analyse it.

== Code style

Format only your hunks (the tree is not fully formatted):
`git diff -U0 HEAD -- src | clang-format-diff -p1 -i`.

Comments go on their own line, above the code:

[code,c]
----
// Something something
int something;

/* Something else that's a
   bit longer */
int something2;
----

Exception: structs and short function calls may take a trailing comment
that fits on the same line, under 80 chars.
